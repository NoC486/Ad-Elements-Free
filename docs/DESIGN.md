# 设计与安全边界

## 上游审查

OKKO 将定位可执行文件、自动启动、远程下载 CSS、页面判断和 CDP 发送写在单个 Python 脚本内。初版复用 CSS、4 秒缓冲及当前页面/新文档双重应用思路；v0.3.1 取消固定缓冲。重写快捷方式持久化恢复、生命周期、连接管理、响应确认及身份核验。初版移除运行时规则下载，v0.3.0 增加用户主动同步 CSS。始终不自动启动 KOOK，也不添加 wildcard Origin。

WPF 比 WinUI 3 少一层 Windows App SDK 部署依赖，适合简单窗口和长期托盘场景。BCL 提供 HTTP、WebSocket、JSON；托盘使用系统 WinForms 组件，快捷方式使用 WScript.Shell COM。没有 Windows Service、驱动、WebView 或第三方运行库。

## 生命周期

开关变更由信号量串行处理，UI 在操作时暂时禁用开关。关闭先取消并等待监控结束，再恢复快捷方式。v0.3.1 启用时先注册 Windows 窗口事件，再做一次进程快照，以覆盖客户端已经运行的情况。未运行时不设定时器、不读取 TCP 端口表、不请求 CDP。窗口通知线程阻塞等待消息，仅筛选顶层窗口的创建/显示事件及其所属进程名称；不读取窗口内容或键鼠输入。

收到目标窗口事件后进入约 30 秒的启动重试窗口，未就绪时每轮结束等待 250 毫秒。调试端口身份核验后，通过 `/json/version` 建立浏览器级 CDP 事件连接，先订阅 `Target.setDiscoverTargets`，再获取一次 `/json` 快照。连接建立后等待页面创建/导航/销毁和断线事件，不再定时查询进程、端口和页面列表。单纯标题变化或已连接客户端的窗口显示不会触发重复查询。启动失败达到期限后停止重试，需新实例、页面事件或用户重新开启开关唤醒。

CDP 会话键包含监听 PID、启动时间及 WebSocket target URL，避免 PID 重用及多个子进程造成重复。同一 target 和 origin/path 不重复注入；查询串和片段变化不重新注册。CSS 在 head 存在时立即应用，尚无 head 时注册一次 DOMContentLoaded 回调，不再固定等 4 秒。刷新由预先注册的新文档脚本处理，新窗口由 CDP 事件处理；同步规则通过重启已启用 Provider 主动重新加载。关闭时移除注册脚本、CSS 及未触发的就绪回调，取消事件等待并卸载窗口通知。

窗口通知并非完整的进程启动跟踪。如果客户端不产生可捕获的窗口事件、运行于其他桌面或存在权限隔离，自动发现可能失败；可在客户端打开后重新开启 Provider，触发一次初始快照。不声称绝对零 CPU/内存占用。WebSocket 不启用周期性 keepalive，所有主动请求有超时及取消令牌。

## 身份与网络

1. `GetProcessesByName("KOOK")` 使用系统进程信息查找名称；只对匹配的 PID 查询路径/启动时间。不周期性打开所有进程句柄。
2. `GetExtendedTcpTable` 读取 IPv4/IPv6 TCP LISTEN 元数据，不打开监听者的进程。非 loopback 绑定即拒绝。
3. 监听 PID 必须来自 KOOK 名称列表；文件名为 KOOK.exe，产品元数据为 KOOK/Kaiheila/开黑啦。其他占用者不打开其进程，直接提示冲突。
4. HTTP 仅访问固定 `127.0.0.1:9222/json` 和 `/json/version`，禁用代理及重定向，有响应大小限制。
5. 页面必须通过 Provider URL 白名单。页面 WebSocket 必须是 `ws://127.0.0.1:9222/devtools/page/...`，事件连接必须是同主机端口的 `/devtools/browser/...`；不接收用户名、查询串或其他主机。
6. 连接后获取 Page.getFrameTree，再核对当前 URL、PID/启动时间和端口归属，才执行规则。脚本本身再次检查顶层页面及固定 origin/path，降低导航竞态风险。
7. .NET ClientWebSocket 不发送 Origin，未添加任何 Origin 放行参数。真实 KOOK Chromium 版本仍需实机验证。

身份策略用于避免误操作其他正常 Chromium 应用，并非抵御已控制本机的恶意攻击者：文件产品信息可伪造，端口核验与连接也不是原子操作。不声称密码学认证。未知版本宁可不处理。

## 快捷方式恢复

Windows 引号和反斜杠规则解析出 token，同时保留原始字符范围。原参数有相同端口时不取得所有权；冲突/重复/未闭合引号时不改写。只追加一次指定参数。

记录在修改之前 flush 并原子替换。恢复时先比较 Target；一致且 Arguments 未变则恢复原字符串；用户新增其他参数时，仅移除本程序拥有的确切端口 token。Target 变化、重复 token 或端口改为其他值则保留记录并提示人工检查。不恢复旧 Target，不覆盖用户新设置。用户删除后又自行添加完全相同 token 的意图无法可靠区分，这是最小差异恢复的固有限制。

## 反作弊约束审查

不含 DLL 注入、线程注入、进程内存读写、键鼠 hook、图形 hook、调试器附加、驱动/服务、进程隐藏或游戏文件操作。v0.3.1 经项目维护者选择，允许一个明确例外：使用全局 `SetWinEventHook` 的 `WINEVENT_OUTOFCONTEXT | WINEVENT_SKIPOWNPROCESS` 窗口事件通知。回调在 AEF 自身线程执行，不向其他程序加载 DLL；只获取事件窗口的 PID 并筛选进程名称。唯一显式 OpenProcess 使用 QUERY_LIMITED_INFORMATION（0x1000），仅限已按名称找到的 KOOK PID，以取得映像路径。不获取 VM_WRITE/VM_READ/ALL_ACCESS，不操作游戏或反作弊服务。

CDP 是 KOOK 自己开启的本机接口；它具有调试能力，所以不应将其描述为零风险。程序不打开监听端口，不放行防火墙，不修改系统安全设置。无法约束用户自行启动 KOOK 时给 Chromium 加入的不安全绑定；检测到非 loopback 监听会拒绝使用并报告。

主程序正常运行 manifest 为 asInvoker，无自动提权。自 v0.1.1 起，安装器可为全用户安装请求权限，以写入 Program Files；也提供不提权的当前用户安装。安装可按用户勾选启动主程序，不修改目录 ACL 或系统安全设置。日志仅写状态与异常类型，限制大小。不会记录 CDP 页面正文、账户内容或 URL。

## v0.2.0 设置

开机自启由用户主动开启，默认不写入；使用当前用户 HKCU Run，命令行引用完整 EXE 路径并带 `--startup`，不创建服务或任务。读取真实注册状态，不另存一个可能失真的 JSON 布尔值；关闭仅删除匹配当前路径的项。便携版移动后需重新开启，Windows 启动应用的禁用优先级保持不变。卸载仅清理执行卸载用户的匹配项，其他用户应自行关闭。

更新检查只在用户点击时请求 GitHub 的本仓库 `releases/latest`，15 秒超时，关闭设置时取消。忽略预发布和草稿，按数字比较正式版本；错误不当作“已是最新”。链接仅由固定仓库 URL 和经过格式校验的标签生成，不使用接口返回的任意 URL，不下载或执行远程代码。

## v0.3.0 外部规则同步

规则只从程序目录 Rules/客户端名称/style.css 加载，无内嵌回退。缺失/不可读时提示同步恢复。每次重新启用会读取最新文件；设置中同步完成会重新启动已启用 Provider 的监控及规则会话。

手动同步从固定仓库 main 获取提交 SHA，再按该 SHA 下载已注册规则目录内的 CSS。仅获取 UTF-8 文本，拒绝空文件、HTML、超大内容，保留旧 CSS 备份；不拉取或执行远程脚本，不接受远程指定的目标路径。受保护目录触发单独的 --sync-rules-elevated 实例，该实例不加载用户配置、不创建 Provider 或托盘，只下载固定规则并写入自身目录，完成即退出。拒绝规则树中的符号链接/目录联接，不修改目录 ACL。

安装新增默认开启的立即运行选项，使用 runasoriginaluser 和 --show-window；静默安装不启动。若用户主动以管理员身份运行安装器，Inno Setup 无法恢复不存在的原始普通用户令牌，应正常双击安装器。
